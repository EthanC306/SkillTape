WRITE coverage across the cpp bank, and a 3-per-session cap on WRITE items
--------------------------------------------------------------------------------
Date:     2026-08-09
Commit:   94d87bb (released as 1.0.12)
Files:    src/data/itemSchema.js, src/components/PracticeView.jsx,
          server/routes/drill.js, test/applyWriteCap.test.js (new),
          src/data/topics/cpp/{stacks,queues,iterators,doubly-linked-lists,
          templates,linked-lists-algorithms,recursion}.js,
          sources/cpp/{doubly-linked-lists,iterators}.md
Summary:
  - Item bank: added WRITE items until every code segment in the stacks,
    queues, iterators, doubly-linked-list and templates decks had one. Stacks
    went 1 WRITE -> 7 (array pop/peek, linked-list ctor/push/pop/peek), queues
    1 -> 5 (class declaration incl. nextIndex, ctor, pop, peek), iterators
    gained one item per operator (*, ->, prefix ++, postfix ++, ==, !=) plus
    the ConstIterator ctor, doubly linked lists gained outputForward/
    outputBackward/length/clear/copy/search and the List destructor, and
    templates gained the Pair class declaration.
  - Two sources/ gaps closed rather than papered over with invented citations:
    Deck 03.3's algorithm slides (output forward/backward, length, clear, copy,
    search) and Deck 04.2's ConstIterator constructor were never ingested, so
    the items citing them had nothing to point at. Both were transcribed into
    sources/ under new anchors, with a dated comment marking them as hand-
    transcribed, and the items re-pointed from provenance:null to EXTRACTED.
  - Three transcription bugs were corrected on the way in, since an `expected`
    answer teaches whatever it contains: copy() walked `head` instead of
    `source.head` (it clear()s first, so the loop would exit immediately and
    leave an empty list), outputBackward called getPrev() where the deck's
    DNode declares getPrevious(), and the lecture's List destructor reads
    cursor->getNext() AFTER deleteNode(cursor) has freed it. The destructor was
    left verbatim — it's what the slide shows and what an exam would mark — but
    the use-after-free is now an explicit grading criterion rather than a
    silent rewrite.
  - Session composition: WRITE is the most expensive format to answer (90-300s
    budgets, all self-graded free text), and the additions above made it easy
    for a 20-item deck to sample eight of them. applyWriteCap() in
    itemSchema.js — the one module both the client and server already import,
    so there is a single definition — caps a MIXED deck at
    MAX_WRITE_PER_SESSION (3) and returns a WRITE-ONLY deck untouched, on the
    grounds that asking for nothing but WRITE is a deliberate choice to sit
    down and write code.
  - "WRITE-only" is read off the deck itself, not off a format picker, which is
    what lets the same function serve the exam route (no picker exists there)
    and still behave correctly when topic/difficulty filters happen to leave
    only WRITE items.
  - Wired into exactly the two places a mixed deck is built:
    PracticeView.startPractice, where the cap runs BEFORE the slice so the
    session still fills to the requested length with other formats instead of
    coming back short; and GET /api/drill/exam, which always caps and now
    recomputes topicMeta.sampled so the exam report can't count items the cap
    removed. The FSRS due queue (GET /api/drill/queue) is deliberately NOT
    capped — dropping due WRITEs there would defer scheduled reviews rather
    than reduce work.
  - Practice's setup screen states the cap when it applies ("max 3 WRITE per
    session (N available) — deselect every other format to drill WRITE on its
    own") and the Start button counts the capped pool, so a shortened deck is
    never a surprise.
  - test/applyWriteCap.test.js covers both rules plus the boundaries (limit
    override, limit 0 still exempting a write-only deck, empty/non-array
    input). Suite: 85 passing.

Auto-update implemented end to end (docs/AUTO_UPDATE_TODO.md Changes 1-9)
--------------------------------------------------------------------------------
Date:     2026-08-07
Commit:   uncommitted
Files:    electron-builder.yml, scripts/release.mjs (new), package.json,

          index.html, README.md, docs/AUTO_UPDATE_TODO.md
Summary:
  - Worked docs/AUTO_UPDATE_TODO.md's Changes 1-9 in order. The plan's
    diagnosis was already verified against the live API and the vendored
    electron-updater source, so this was implementation, not re-diagnosis.
  - Release side: electron-builder.yml keeps releaseType at the default
    `draft` (NOT `release` — gitHubPublisher.js's `if (release.draft) return
    release` reuses an existing draft and never flips it, so releaseType only
    ever applies at creation time and one stale draft poisons its tag
    permanently). scripts/release.mjs owns the flip instead: preflight
    (GH_TOKEN present, plain x.y.z semver, strictly newer than the published
    latest, NO existing release for the tag — authenticated, since that's the
    only way drafts are visible — clean git tree), then
    `npm run electron:publish:win`, then asset verification (latest.yml,
    SkillTape-Setup-<v>.exe, .blockmap all present and non-zero, plus
    latest.yml's `path:` matching the real asset name), then PATCH
    draft:false. Uploading into a draft and publishing last means
    releases.atom — the feed electron-updater actually reads — can never
    advertise a half-uploaded release. nsis.artifactName set to the
    space-free ${productName}-Setup-${version}.${ext} to delete the
    upload/download filename-normalization mismatch class outright.
  - App side: main.cjs replaces checkForUpdatesAndNotify() with a single
    module-level `updateState` (idle|checking|available|downloading|ready|
    error|unsupported) that every event handler mutates and pushes over
    "updater:state". Both existing failure guards were kept and are still
    load-bearing (offline launch is the ordinary case, and electron-updater
    reports it twice — an "error" event AND a rejected promise). Added
    electron-log so a packaged Windows app has any diagnostic at all
    (%APPDATA%\SkillTape\logs\main.log); the absence of one is half of why
    this stayed broken unnoticed. ipcMain.handle("updater:getState") exists
    specifically for the mount race — on a fast check the events fire before
    React mounts, so a subscribe-only banner sits empty through a live
    download. stopBackend() is now deterministic (await exit, SIGKILL after
    2s) and before-quit preventDefaults once to await it, because
    autoInstallOnAppQuit runs NSIS on the `quit` event and a still-running
    forked SkillTape.exe holds file handles in the install dir.
  - UI: preload.cjs went from "intentionally empty" to a narrow contextBridge
    (getVersion + updater.getState/onState/quitAndInstall — no ipcRenderer
    exposure; the window loads http://127.0.0.1:3001/, so a generic invoke
    would hand every handler to whatever runs in that page).
    useUpdater.js pull-then-subscribes and reports "unsupported" when
    window.skilltape is absent, so UpdateBanner.jsx can be mounted
    unconditionally in Shell.jsx and renders null in browser/Docker/dev.
    Banner carries className="app-chrome" so drill/exam mode hides it —
    an update notice is exactly what closed-book mode exists to suppress,
    and the install happens on quit regardless of whether anyone saw it.
    index.html's purple AUTO-UPDATE SMOKE TEST MARKER deleted, replaced
    permanently by the muted v{version} badge next to "View on GitHub".
  - Fixed two crashers in the pre-existing uncommitted working tree along the
    way, both in Shell.jsx and both blocking any verification of the above:
    an undefined bare identifier `purple` used as a style value (immediate
    ReferenceError on render of the home page), and a tab id mismatch where
    the nav emitted "c++"/"cs3000" while the render branch compared against
    "C++"/"Discrete", so neither course tab did anything.
  - Verified here: preflight aborts by name with GH_TOKEN unset; a real
    Chromium load of the served app renders no banner and no badge with zero
    page errors and no purple bar, and both course tabs now switch; unpacked
    `npx electron .` boots the backend and logs "[updater] unpacked run —
    update checks are skipped" through electron-log, then exits clean;
    npm test (68 pass) and npx vite build unchanged; audit:bank at its

  - NOT verified, and not verifiable from this Linux shell: the actual update
